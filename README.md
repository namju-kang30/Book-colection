# 진로 맞춤형 차시별 독서 활동 일지 (Realtime Reading Log Platform)

학생들이 자신의 희망 진로 계열(자연과학, 공학, 인문사회, 의약보건 등)을 선택하고, 활동 차시별로 독서 일지를 간편하게 작성·공유할 수 있는 모바일/데스크톱 반응형 웹 애플리케이션입니다.

---

## 🌟 주요 특징 및 기능

### 1. 학생용 기능 (Student Portal)
- **진로 계열 & 차시별 필터링:** 8대 핵심 진로 계열별(자연과학, 공학·IT, 인문·사회, 의약·보건, 교육·사범, 경영·경제, 예술·체육, 융합·자율) 뱃지 및 차시 필터
- **공통 양식 동적 렌더링 폼:** 교사가 설정한 최신 양식(도서명, 저자, 읽은 범위, 인상 깊은 구절, 진로 연계 통찰, 별점 등) 자동 로드
- **실시간 피드 & 상세 보기:** 작성된 일지를 카드 그리드로 열람, 전문 상세 보기 모달, 인쇄 및 공감(좋아요) 반응
- **작성 편의성:** 최근 입력한 학번/이름 자동 기억, 작성 완료 시 축하 폭죽 애니메이션 & 즉각 피드 갱신

### 2. 선생님 / 관리자 모드 (Admin Dashboard)
- **보안 관리자 인증:** 코드 내 평문 암호를 노출하지 않는 **SHA-256 단방향 암호화 해시 검증** 방식 적용
- **독서일지 양식 빌더 (Template Builder):** 질문 항목명, 입력 형태(단문/장문/별점/숫자), 필수 여부, 안내문구(Placeholder)를 시각적으로 추가/수정/삭제/순서변경
- **일지 통합 관리 & Excel 다운로드:** 전체 제출 일지 조회, 개별 삭제, **Excel(.xlsx) 및 CSV 일괄 다운로드**
- **진로 계열 관리:** 진로 계열 추가, 색상/아이콘 지정, 삭제
- **활동 차시 관리:** 활동 차시명, 활동일자 등록, 활성화/마감 토글
- **Supabase 원클릭 연동:** 접속 키 설정, 연결 상태 진단, **SQL 스키마 원클릭 복사**

## 🚀 빠른 시작 방법

### 방법 1. 원클릭 실행 (Windows)
`start.bat` 파일을 더블 클릭하여 실행하면 로컬 서버가 구동되고 브라우저(`http://localhost:3000`)가 자동으로 열립니다.

### 방법 2. 파이썬 터미널 실행
```bash
python run_server.py
```
브라우저에서 `http://localhost:3000` 으로 접속합니다.

## 🗄️ Supabase 클라우드 데이터베이스 연동 가이드

이 리포지터리는 기본 Supabase 프로젝트 설정을 포함합니다. 서버가 설정되어 있으면 일지는 서버 저장 성공을 확인한 뒤 제출 완료로 표시합니다. 서버 오류가 발생하면 입력 내용을 유지하며, 자동으로 로컬 제출로 전환하지 않습니다. 설정을 명시적으로 비운 로컬 모드에서는 이 브라우저의 LocalStorage에 저장됩니다.
실제 학교 또는 학급 전체 학생들이 실시간으로 공유하게 하려면 아래 절차를 진행하세요:

1. [Supabase](https://supabase.com)에 로그인하고 무료 프로젝트를 생성합니다.
2. 좌측 메뉴의 **SQL Editor**로 이동합니다.
3. 본 프로젝트의 `supabase_schema.sql` 파일 내용(또는 관리자 화면의 **[SQL 전체 복사]** 버튼 내용)을 붙여넣고 **[Run]**을 실행합니다.
4. Supabase **Project Settings -> API**에서 아래 2개 값을 복사합니다:
   - `Project URL`
   - `Project API Keys`의 `anon` (public) 키
5. 웹앱 상단의 **[로컬 모의모드]** 또는 관리자 화면의 **[Supabase 연동 & SQL]** 탭에 입력하고 **[설정 저장 및 연동]**을 누르면 실시간 클라우드 DB 연동이 완료됩니다!

## JSON 백업 및 불러오기

관리자 로그인 후 **JSON 백업 & 불러오기** 탭에서 사용할 수 있습니다.

1. **JSON 파일로 백업**: 화면의 검색·필터와 관계없이 현재 저장소의 전체 일지를 다운로드합니다. 계열, 차시, 양식, 원래 ID·작성일·공감 수·학생 정보·비밀번호 해시가 포함됩니다. Supabase에서는 여러 페이지를 조회해 1,000건 이상도 백업합니다. 서버 조회에 실패하면 오래된 브라우저 캐시로 백업 성공을 표시하지 않습니다.
2. **파일 선택**: 이 앱에서 생성한 JSON 파일(최대 20MB)을 선택합니다. 전체 구조, ID, 날짜, 참조 관계를 검증하고 건수를 표시합니다. 검증 실패 시 데이터를 변경하지 않습니다.
3. **확인한 데이터 불러오기**: 확인 후 누락된 ID만 추가합니다. 기존 일지와 계열·차시·양식 설정은 덮어쓰지 않습니다. 같은 파일을 반복해서 불러와도 중복되지 않습니다. 현재 활성 양식이 있으면 추가 양식은 비활성 상태로 보관합니다. 로컬 모드에서는 현재 활성 양식만 보관합니다.

백업은 현재 연결된 Supabase 또는 현재 브라우저 저장소의 데이터를 대상으로 합니다. API 접속 키와 관리자 비밀번호 설정은 포함하지 않습니다. 학생 개인정보와 본인 확인용 해시가 들어 있으므로 파일을 안전하게 보관해 주세요.

클라우드 불러오기는 계열 → 차시 → 양식 → 일지 순서로, 최대 250건씩 추가합니다. 여러 요청 전체가 하나의 트랜잭션은 아닙니다. 중간 오류가 발생하면 일부 데이터가 추가될 수 있으며, 화면에서 실패를 알립니다. 연결 복구 후 같은 파일을 다시 불러오면 기존 ID를 유지하며 나머지를 추가할 수 있습니다. 로컬 불러오기는 저장 오류 시 원래 데이터로 되돌리기를 시도합니다.

## 동작 검증

Node.js 24 이상에서 `npm test`로 저장·복원 회귀 테스트를 실행합니다. npm 패키지 설치는 필요하지 않습니다.

브라우저 검증에는 Python 3.12와 Playwright가 필요합니다:

```bash
python -m pip install playwright==1.62.0
python -m playwright install chromium
python tests/browser_smoke.py
```

브라우저 테스트는 데스크톱·모바일 화면에서 제출·비밀번호 확인·수정·삭제, JSON 파일 다운로드와 검증·불러오기, 서버 실패 후 재시도, 응답 유실 시 중복 방지, 브라우저 저장 차단, 여러 별점 질문, 실시간 갱신 후 필터 해제를 확인합니다. 외부 스크립트와 Supabase는 테스트용 응답으로 대체하며 실제 학생 데이터나 운영 DB를 변경하지 않습니다. GitHub Actions에서도 이 검증을 실행합니다.
